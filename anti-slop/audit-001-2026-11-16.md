# Audit 001: background dither and card contrast

Date: 2026-11-16. Mode: after (audit only, nothing changed).
Scope: the orange ordered-dither background (`DitherBackground.vue`, `public/dither-corner.png`), the translucent
cards (`--card` at 60%), and the controls that sit on them (tabs, inputs, selects, badges), in light and dark mode.
Branch: `feature/dither-background` (uncommitted).

Method: WCAG relative-luminance ratios computed from the tokens in `web/app/assets/css/main.css`, compositing
every translucent layer (page, 12%/20% orange dither dot, 60% card, 60% input fill, 10% badge fill). "Over a dot"
means the worst pixel, where a dither dot sits directly under the text. Visual review from headless Chrome
screenshots of the overview, alerts, sites and login pages.

## Findings

| # | Priority | Rule | Finding |
|---|---|---|---|
| 1 | HIGH | R-34 | The sign-in page never applies dark mode (it uses `layout: false`, and only the default layout calls `useDark`). A user in dark mode is logged out to a light page, and the dark login dither (`dark:opacity-60`) is dead code that has never been seen. Predates the dither. |
| 2 | HIGH | R-39 (non-text contrast) | Input, select and textarea borders are 1.64:1 (light, `#CFC8BF` on the card) and 1.75:1 (dark, `rgb(239 234 228 / 20%)`) against the surface behind them. A field's boundary needs 3:1 so low-vision users can find it. Predates the dither; the translucent fill did not change the ratio. |
| 3 | HIGH | R-39 (selected state) | The selected tab is marked by a fill that is 1.16:1 (light) and 1.14:1 (dark) against the tab bar, plus a faint `shadow-sm`. In practice the only strong cue is the text color (foreground vs muted), so the selected state rests on color. It needs a non-color cue or a 3:1 indicator. |
| 4 | LOW | C-4 | In Windows forced-colors mode the canvas and the PNG corners still paint orange dots, because forced colors do not recolor canvas or background images. Hide `.dither` and `.dither-canvas` under `@media (forced-colors: active)`, as already done for `prefers-contrast: more`. |
| 5 | LOW | C-4 | Under `prefers-contrast: more` the dither is hidden, but cards stay 60% translucent, which flattens the card edge against the page (border 1.25:1 light, 1.30:1 dark). Make `--card` opaque under the same media query. |
| 6 | LOW | R-31 | The densest part of the top-left fade sits directly under the page title and its description. Every ratio still passes (worst: muted description over a dot, 5.35:1 light, 5.98:1 dark), but the 2 px checker has the same spatial frequency as 14 px text strokes, so the description reads noisier than in a card. This placement was requested; listed so the trade-off is a recorded decision, not an accident. Options: start the top-left fade below the header row, or lower its density only. |

## Passed checks

Text contrast, worst case over a dither dot (minimum 4.5:1):

| Surface | Light | Dark |
|---|---|---|
| Page title on page | 14.98 | 13.01 |
| Page description (muted) on page | 5.35 | 5.98 |
| Card text | 16.97 | 14.40 |
| Card muted text | 6.07 | 6.62 |
| Input placeholder (muted) | 6.37 | 6.82 |
| Badge `crit` / `warn` / `ok` in a card | 4.90 / 5.14 / 4.91 | 5.46 / 7.47 / 6.92 |
| Sign-in card muted text over a corner dot | 5.48 | 5.12 |

- Focus: the focused field's solid orange border is 3.34:1 (light) and 5.87:1 (dark) against the card, which meets
  3:1. The 50% halo around it is 1.85 and 2.29 and is supplementary only.
- Popovers, dropdowns, dialogs and tooltips stay opaque (`--popover`), so menus never show the pattern.
- R-07: the dither has a written identity purpose in `DESIGN.md` (section 6, "Background dither").
- Text on the sign-in page sits only inside the card; the corner dots reach the card only on narrow screens,
  where the worst ratio is 5.12:1.

Not checked: the sign-in page in dark mode (finding 1), forced-colors and `prefers-contrast` by emulation
(findings 4 and 5 come from code inspection), and screen magnification.
